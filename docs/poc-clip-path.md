# T1：clip-path PoC 測試

> 目的：驗證 SPEC 第 6 節方案 A 的關鍵前提。對 `ytd-live-chat-frame` 套 `clip-path` 後，被裁掉的上半部收到的點擊和滾輪，要穿透到下層的測試面板；底部露出的原生輸入框仍要能正常打字。
> PoC 程式：`src/poc/clip-path-poc.js`（只在 top frame 執行，T6 完成後移除）。

## 狀態
- 模擬頁面（非 YouTube）自動檢查：✅ Chrome 156.0.8078.75 下 `elementFromPoint` 確認，裁切區域命中測試面板，未裁切區域命中 iframe 和「隱藏聊天室」列。
- **真實 YouTube 直播：⬜ 待使用者實測**（以下步驟）。

## PoC 行為
- 頁面左下角有藍色「PoC：開啟」按鈕（快速鍵 Alt+Shift+P）。
- 開啟後：
  - 在原生聊天室正後方放一個同位置、同尺寸、藍色虛線框的「測試面板」（z-index 10）。面板內有 200 個「測試列」按鈕，以及點擊次數和滾輪次數統計。
  - 原生 `ytd-live-chat-frame` 移到上層（z-index 20）並套用 `clip-path`。預設從 iframe 底邊往上只露出 **84px**（可用滑桿調整 40–240px），iframe 下方的原生「隱藏聊天室」列也會一起露出。
  - 可切換裁切對象：`ytd-live-chat-frame`（預設，SPEC 方案）或 `iframe#chatframe`（比較用）。
- 再按一次（紅色「PoC：關閉」）完全還原。

## 測試前準備
1. **停用舊版 v2.6.0 套件**：到 `chrome://extensions` 關閉舊的「YT Live Chat Memory Saver & Archiver」（它的資料夾已改名成 `yt-chat-archiver-saver_v2.6.0_backup`，可能已顯示錯誤，關掉或移除都可以）。
2. 點「載入未封裝項目」，選 `E:\Tool\ChromeExtensions\yt-chat-archiver-saver`。
   - 檢查 T0：卡片上沒有紅色「錯誤」按鈕，版本顯示 `3.0.0-dev`，圖示是藍綠色對話泡泡。
3. 開一個**你能留言的直播**，確認右側原生聊天室是展開的。

## 測試步驟
1. 按左下角「PoC：開啟」。
2. **看畫面**：聊天室區域應該變成藍色虛線框的測試面板，底部只露出原生輸入框（約 84px）和「隱藏聊天室」列。
   - 如果露出的高度不剛好（露出太多訊息，或輸入框被切掉），用面板上的「露出高度」滑桿調到剛好，**記下數字**。
3. **點擊穿透**：點面板上半部任一「測試列」，該列會變綠色，「點擊」數字 +1，「最後點擊」顯示該列編號。
4. **滾輪穿透**：游標停在面板上半部滾動滑鼠，列表要能捲動，「滾輪」數字會增加。
5. **輸入框**：點底部露出的原生輸入框，打幾個字，確認看得到文字（可以送出，也可以清掉不送）。
6. （加分）點表符按鈕 😊：選單被裁切或看不到都屬正常，F-10 完整的彈窗處理在 T6 才做。只要觀察選單有沒有打開即可。
7. 把裁切對象切成 `iframe#chatframe`，重複步驟 3–5，看結果是否一樣。
8. 切換劇院模式，面板是否仍與聊天室重疊。
9. 按「PoC：關閉」，原生聊天室要完全恢復原狀。
