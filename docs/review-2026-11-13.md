## 3. 遺漏與風險（依重要度）

### 3.1 ⚠️ v2.6.0 舊資料可能遺失或衝突（最高優先）

**原因**
- Chrome 未封裝擴充功能的 ID 由**資料夾路徑**決定，IndexedDB 綁定在該 ID 底下。
- 舊資料夾改名為 `yt-chat-archiver-saver_v2.6.0_backup`，並在原路徑 `E:\Tool\ChromeExtensions\yt-chat-archiver-saver` clone 新 repo。
- 因此 Chrome 裡**原本那個擴充功能項目**（舊 ID、舊資料）重新載入時，讀到的已經是 v3 程式碼。舊資料仍在這個 ID 底下。

**風險**
1. `docs/poc-clip-path.md` 寫「關掉或**移除**都可以」——**移除擴充功能會連同 IndexedDB 一起刪除，舊資料會永久遺失。**
2. 若再對同一路徑按「載入未封裝項目」，可能造成重複或取代項目，有遺失資料的風險。
3. 若 v2.6.0 的資料庫名稱也是 `ytChatArchive` 且版本號 > 1，v3 以 `DB_VERSION: 1` 開啟會發生 `VersionError`；若 v3 的 `onupgradeneeded` 寫法不當，也可能清掉舊資料表。
4. v3 的 `db.js` 目前是空殼，**尚未開過資料庫，舊資料目前應該還在**。

**必須做的事（在任何 Chrome 實測前）**
1. 修正 `docs/poc-clip-path.md` 與 `docs/HANDOFF.md`：
   - 刪除「移除」字樣，改為：**絕對不要移除原本的擴充功能項目，只能在該項目上按 🔄 重新載入。**
   - 不要對同一路徑再按「載入未封裝項目」。
2. 請使用者先做原始備份（寫進測試步驟第 0 步）：
   1. 在 `chrome://extensions` 記下該項目的 **ID**。
   2. 關閉 Chrome。
   3. 複製資料夾 `%LOCALAPPDATA%\Google\Chrome\User Data\Default\IndexedDB\chrome-extension_<ID>_0.indexeddb.leveldb`（若使用其他 Chrome 設定檔，`Default` 改為該設定檔資料夾名稱）到安全位置。
3. 讀取 `E:\Tool\ChromeExtensions\yt-chat-archiver-saver_v2.6.0_backup` 中的 `db.js`（及匯出 JSON 的程式），記錄：
   - 資料庫名稱、版本號
   - 各 object store 名稱、keyPath、索引、欄位
   - v2.6.0 匯出 JSON 的格式
   寫入新文件 `docs/legacy-v2.6.0-data.md`。

### 3.2 PoC 下層面板是 div，正式版是 iframe
- 正式版優化面板是 `viewer.html?embed=1`（擴充功能 origin 的 iframe），形成「iframe 疊在 iframe 下方」。
- PoC 下層只是普通 div，沒有驗證到「裁切區的點擊/滾輪能否穿透到下層 iframe」。

### 3.3 PoC 沒有測「解除裁切」後的原生彈窗
- 滑桿最大 240px，無法測完整高度下表符選單、`$` 選單是否正常向上展開、是否留空白。這是 F-10 的核心前提之一。

### 3.4 `$` 付款視窗可能開在 top frame
- YouTube 部分付款確認視窗會開在整頁中央（top frame 的 `ytd-popup-container` 等），不在聊天室 iframe 內。
- SPEC 6.3 只在 chat frame 偵測彈窗，會漏掉這種情況（top frame 的視窗本身不受 clip-path 影響，但狀態機需要知道它開著）。
