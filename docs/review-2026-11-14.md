## 3. 不足與問題（依重要度）

### 3.1 ❌ 劇院模式錯位（必修）
- **原因**：PoC 把面板插在 `ytd-live-chat-frame` 的父元素裡，再用 `getBoundingClientRect()` 算座標，並每秒 `setInterval` 重排。劇院模式會把聊天室搬到另一個容器（如 `#panels-full-bleed-container`），父元素與座標系都改變，算出的位置就錯了。
- **改法**：改為**錨定在聊天室元素內部**，不再算座標：
  1. 面板插入 `ytd-live-chat-frame` 內（作為 `iframe#chatframe` 的前一個兄弟），`position:absolute; inset:0 0 auto 0; height: <iframe 高度>`，`ytd-live-chat-frame` 設 `position:relative`。面板就會跟著聊天室一起被 YouTube 搬家。
  2. clip-path 改套在 **`iframe#chatframe`** 本身（步驟 8 已證實效果相同），z-index：iframe 20、面板 10。「隱藏聊天室」列不在 iframe 內，自然維持可見，不需另外計算。
  3. 用 `MutationObserver` 監看 `ytd-live-chat-frame` 的 childList：YouTube 若重新渲染把面板移除，就重新插入。
  4. 移除 `setInterval` 輪詢重排；面板高度用 `ResizeObserver` 監看 iframe。
- 寫入 SPEC 6.2、6.4（取代「同一 position:relative 容器」的寫法）。

### 3.2 ❌ 頁面層付款視窗沒被偵測到（必修）
- 截圖 2 的「完成購買程序」開在頁面中央，但 `top.popups`（包含 `ytd-popup-container > *` 萬用規則）沒有抓到，表示這個視窗**不在 `ytd-popup-container` 內**，可能是直接掛在 `body` 下的對話框或跨來源付款 iframe。
- **改法**：
  1. 給使用者一個小工具指令（見 4.3），在付款視窗開著時，於 top frame Console 執行，列出 `body` 底下可見、z-index 高、面積大的元素標籤、id、class、以及其中 iframe 的 `src` 網域。**不要**記錄或輸出視窗內的文字內容（含付款卡資訊）。
  2. 依結果把實際選擇器加入 `selectors.js` 的 `top.popups`，並移除 `ytd-popup-container > *` 萬用規則，改為明確清單。
- **F-10 狀態機影響**：付款流程中，聊天室內的 `buy-flow-renderer` 仍是開啟狀態，所以 clip 本來就會維持「解除」；頁面層視窗主要用於「關閉後回到收起狀態」的判斷不要過早觸發。SPEC 6.2 表格「top frame 付款視窗」列依此補完：**頁面層付款視窗開啟期間，clip 維持解除；兩邊都關閉後才回到收起狀態。**

### 3.3 ⚠️ 露出高度不能寫死（確認）
- 實測 84px / 58px 都有出現，證實 SPEC 6.3「以 `ResizeObserver` 量 `#input-panel` 實際高度」是必要的。
- **改法**：
  - SPEC 6.3 明訂：`inputHeight` = `#input-panel` 的 `getBoundingClientRect().height`，**不得**使用常數 84；`constants.js` 不可出現 84 作為預設裁切值（PoC 除外）。
  - PoC 補一個「自動」模式：由 chat frame 量測 `#input-panel` 高度並 `postMessage` 給 top frame，控制盒顯示「量測值」與「目前露出值」，讓使用者驗證量測結果在兩種狀態下都正確（見 4.3 補測）。
  - 請在報告中說明 58px 與 84px 兩種狀態分別是什麼情況（例如輸入框上方是否有額外提示列），寫入 `docs/poc-clip-path.md`。

### 3.4 ❌ 浮動控制盒遮擋畫面（使用者硬性要求）
使用者原話：「跳出的控制盒會蓋到畫面的一部分，影響觀看體驗。這邊一定要調整，否則不予使用。」

- **說明給使用者**：控制盒是 PoC 測試工具，正式版（T9）會整個移除；正式版的開關是 F-09 整合在聊天室「開啟面板」旁的按鈕，不會有浮在影片上的元素。
- **但規格要把這條寫死**，避免之後任何階段再出現：
  - SPEC 第 10 節新增 **10.1 原則 6：「不遮擋影片與頁面主體」**——套件在 YouTube 頁面上的所有 UI（按鈕、面板、提示、設定）只能出現在**聊天室區域內**或**擴充功能 popup / 後台分頁**；不得有 `position:fixed` 浮在影片、標題、留言區上的元素；暫時提示（toast）也只能出現在面板內部。
  - 第 7 節非功能需求新增一列「版面侵入」：同上，並列為每個 ⏸ 關卡的檢查項。
  - `docs/test-checklist.md` 新增一項：「影片與頁面主體上沒有任何套件元素」。
- **PoC 本身也要改**（因為之後還要補測）：
  1. 刪除左下角浮動「PoC：開啟」按鈕與浮動控制盒。
  2. 開關改放在原生聊天室「隱藏聊天室」那一列的右側（即 F-09 按鈕的預定位置），文字「PoC 測試」。也保留 Alt+Shift+P。
  3. 控制項改放在**測試面板頂部**的一列，可收合（預設收合，只顯示一行狀態）。
  4. 「完全不裁切」時面板被原生聊天室蓋住的問題：改成**快速鍵切換**（Alt+Shift+U）＋聊天室列旁的小按鈕，不需要按到面板內的控制項。

### 3.5 ⚠️ 「按下去才顯示」的預期落差（需使用者決定）

  - 直播與有聊天重播的 VOD 都套用；沒有聊天室的影片不顯示任何東西。
