## 3. 問題分析

### 3.1 ❌ 露出高度：量測對象不該是 `#input-panel`
**證據**
- 截圖 1、6：輸入列（56px）**上方還有一條原生「置頂訊息列」**（`@阿成x … 1. 尊重彼此…`），兩者合計約 114px。這就是前次 58px／84px／本次 114px 差異的來源。
- 截圖 2：有**投票卡片**時，投票卡浮在訊息列表底部、輸入列上方，總高度超過 240px。

**結論**
- YouTube 目前版面在訊息列表與輸入列之間，還會出現：置頂訊息列、投票／問答卡、（可能）會員里程碑橫幅等「底部錨定」元素。這些都屬於原生互動區，**都必須露出**，否則被裁掉後使用者看不到也點不到。
- 因此 `inputHeight` 的定義要改為 **「底部互動區高度」= iframe 底邊 − 所有可見底部錨定元素中最高者的頂端**。

**但目前不知道這些元素的標籤名稱**，不能憑猜測寫選擇器。先補診斷（4.1），拿到結構再定案。

### 3.2 ❌ 劇院模式與窄版面不可用
**證據**
- 截圖 3、4（劇院模式）：面板只剩頂部狀態列（約 40px），其下直接是原生訊息。面板位於右側推薦影片欄的位置。
- 截圖 5（窄版面）：同樣只剩狀態列。
- 兩種情況下原生聊天室本身看起來也是「縮小／摺疊」狀態（只有約 150px 高）。

**可能原因（需診斷確認，不要直接修）**
1. 劇院模式下 YouTube 把 `ytd-live-chat-frame` 搬到 `#panels-full-bleed-container` 或摺疊成矮高度，`iframe#chatframe` 高度遠小於露出值 114px → `inset(calc(100% - 114px) 0 0 0)` 變成負值 → clip 等同無效，原生訊息蓋住面板。
2. 面板高度綁定 iframe 高度，iframe 變矮時面板也只剩狀態列的高度。
3. `ytd-live-chat-frame` 在劇院模式可能帶有 `collapsed`／`theater` 之類的屬性或換了父容器，`ResizeObserver` 沒有觸發重新排版。

**無論哪種原因，正式版的規則都要補上**：
- 露出值必須 **clamp 在 `[0, iframe 高度]`**；當 iframe 高度小於某閾值（例如 < 200px），視為「聊天室摺疊／不可用」狀態，**自動解除 clip、隱藏面板，不干擾原生聊天室**，待高度恢復再啟用。
- 監看 `ytd-live-chat-frame` 的屬性變化（`collapsed`、`theater`、`class`）與父元素變更，觸發重新計算。

### 3.3 ✅ 付款視窗偵測：定案
- `selectors.js` `top.popups`：`'#buyFlowDivId'`（主）、`'body > .modal-dialog-bg'`（遮罩，輔助）。`b3-modal-dialog*` 這類 class 僅作次要比對，不可單獨依賴。
- 可見判定沿用 review-2 §3.2（rect 寬高 > 0 且非 display:none／visibility:hidden）。
- `iframe#buyFlowDivIdIframe` 網域 `payments.youtube.com`，跨來源，**不讀取、不注入**。
- 移除 `ytd-popup-container > *` 萬用規則（review-2 已要求）。
- PoC 的「頁面浮層」偵測已能抓到，正式版沿用「明確選擇器為主、fixed 掃描為輔」。

### 3.4 新版面的「置頂訊息列」與 F-07 的關係
- 新版面把置頂訊息放在輸入列正上方（截圖 1、6），而不是舊版的聊天室頂部橫幅。
- 影響：
  1. F-10：這條列屬於底部互動區，必須露出（見 3.1）。
  2. F-07「懸浮置頂卡片」：面板內仍要顯示（因為訊息列表被我們接管），但**不得與原生那條列功能衝突**，例如點擊展開時不應互相遮蓋。D1 設計稿需考量這一點。
  3. F-02 擷取：置頂訊息的 DOM 來源可能改變（不一定在 `yt-live-chat-banner-manager`），`selectors.js` 的 `chat.bannerContainer` 需在診斷中一併確認。

## 4. 追加任務（併入 v24，接在 review-2 §4 之後）

### 4.1 PoC 診斷強化（`test: PoC 新增版面診斷與底部互動區量測`）
1. **底部互動區診斷**（chat frame，`poc-chat.js`）：列出 `yt-live-chat-renderer` 底下所有**可見**且 `rect.bottom > iframe 高度 − 400` 的元素（排除 `#item-list` 及其子孫），輸出 `tag#id`、`top`、`height`、父鏈前 3 層；**不輸出任何文字內容**。顯示在面板狀態列，並提供「**複製診斷**」按鈕（需使用者手勢才能寫剪貼簿）。
2. **自動量測 v2**：露出值 = iframe 高度 − 上述清單中最小的 `top`（即最高的底部元素頂端）；仍同時顯示舊算法（`#input-panel`）供比對。滑桿上限改為 iframe 高度。
3. **版面診斷**（top frame）：狀態列顯示 `ytd-live-chat-frame` 的父元素、屬性清單、frame／iframe／面板三者的 rect、目前計算出的 clip 字串、是否觸發「摺疊」保護。同樣可一鍵複製。
4. **摺疊保護**：iframe 高度 < 200px 或露出值 ≥ iframe 高度時，自動 `clip-path: none`、隱藏面板、狀態列顯示「聊天室摺疊，PoC 暫停」；高度恢復自動重啟。監看 `ytd-live-chat-frame` 的 `attributes` 與 `childList`、以及其父元素變更（`MutationObserver` 於 `ytd-watch-flexy`）。
5. **付款視窗**：`top.popups` 依 3.3 定案，移除萬用規則。
