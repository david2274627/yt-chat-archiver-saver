## 3. 分析

### 3.1 投票卡在 `div#action-panel`，不在覆蓋層
診斷（有投票、無置頂列的直播）：`div#action-panel`，top 355／高 182，父鏈 `div#chat < div#contents < div#chat-messages`，被標「未列入」。
- `chat.bottomZone` 白名單加入 **`#chat > #action-panel`**（可見且高度 > 0 才計）。此例露出值 = 594 − 355 = **239px**。
- `yt-live-chat-action-panel-renderer`、`yt-live-chat-poll-renderer` 是否為其子元素仍未確認，維持「待實機確認」。
- 合理性檢查調整：對**白名單元素**只保留「面板可見高度 ≥ 160px」一條；「> 60%」只套用在覆蓋層子元素等非白名單來源。
- 面板可見高度不足 160px 時（例如矮視窗＋投票卡），正式版行為：照樣完整露出原生互動區，面板縮到剩餘空間；剩餘 < 80px 時視同摺疊退讓。寫入 SPEC 6.2。

### 3.2 劇院模式切回後不恢復
已知事實：
- 劇院模式下 `ytd-live-chat-frame` 從 `#secondary-inner` 被搬到 `#columns`。**iframe 在 DOM 中被搬移會重新載入**，chat frame 的 content script 會重跑、舊的量測值失效。
- 劇院模式診斷：iframe 高 150，但聊天室內容仍以約 320px 排版（置頂列 top 211、輸入列 top 263，都在可視範圍外），`zoneFromBottom = −61`。也就是說**此版面下 YouTube 自己就把輸入列擠出畫面**，套件退讓是正確行為。
- 切回後的診斷沒有取得，原因未定。可能方向（請實際查證，不要只猜）：(a) `state.measure` 停在重載前的舊值、新 chat frame 的量測訊息因 `event.source` 比對到舊 `contentWindow` 被丟棄；(b) `ResizeObserver`／`MutationObserver` 在搬移後未重新綁定；(c) 面板節點在搬移時被移除後未重建。
- 要求：搬移或 iframe `load` 事件後，**重置量測狀態、重新握手、重綁 observer、重新套用 clip**；加入 `log('恢復流程', 原因)`。正式版（T6）沿用同一套「重新初始化」流程，寫入 SPEC 6.4。

### 3.3 VOD 重播（`/live_chat_replay`）結構
- `yt-live-chat-renderer` 屬性：`hide-timestamps`, `has-ticker`, `enable-banner-update`（沒有 `has-input-action-panel`）。
- `#input-panel` 存在但**高度 0**；置頂列高度 0 → `bottomZoneHeight = 0`，面板佔滿全高。與 SPEC「無輸入區」狀態一致。
- `span#timestamp` 有值（長度 4，如 `1:23`，CSS 隱藏）→ **重播可直接由 `#timestamp` 得到 `videoOffsetSec`**。
- 重播也有「重點／全部」切換選單（2 個 `a`）→ F-12 同樣適用於重播。
- 新確認的訊息元件：
  - `yt-live-chat-membership-item-renderer`：屬性 `has-primary-header-text`；`#card > #header（#author-photo img#img, #header-content: #author-name, #chat-badges, #header-primary-text, #header-subtext, div#timestamp）+ #content > #message`
  - `ytd-sponsorships-live-chat-gift-redemption-announcement-renderer`（收到贈送會員；結構未展開）
  - `yt-live-chat-placeholder-item-renderer`（佔位元素，**擷取時略過**）
  - `yt-live-chat-ticker-sponsor-item-renderer`（跑馬燈內的會員項目：`#container > #content > #author-photo, #text`）
  - `author-type=member` 確認。
- 仍未出現：SC 文字版、超級貼圖（重播）、gift-purchase、降落、里程碑。

方案 A 的所有前提與周邊機制（錨點、量測、付款視窗、摺疊退讓、不遮擋影片）都已在實機成立；剩餘兩點是 PoC 實作缺陷，不影響方案。**T1 通過，關閉 T1 關卡。**
