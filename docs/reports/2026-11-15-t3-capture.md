### 1.1 T3 內容
- **嵌入式 chat frame**：
  - 網址通常沒有 `v`，所以 `videoId` 由 top frame 的 `STREAM_INFO` 提供。
  - `STREAM_INFO` 也帶開播／結束時間和影片長度。
  - 收到前每秒重送要求，30 秒內沒收到就改用網址參數；仍取不到則只修剪、不收錄。
- **彈出式聊天室**（頂層的 `/live_chat`）：
  - `videoId` 取自網址；`capture_sessions.source = 'popout'`。
  - background 先抓 watch 頁的 meta，取得開播時間、標題、頻道，最多等 5 秒；拿到頻道後才判斷 F-15 暫停。
  - 重播版彈出視窗（`/live_chat_replay`）記為 `replay`。
- **擷取**：
  - 開始時先回溯擷取 `#items` 既有訊息。
  - 之後由 `MutationObserver` 擷取新節點，處理過的節點標 `data-ytcas-saved`。
  - 解析的類型：文字、會員（標題／副標放在 `runs` 開頭）、SC、超級貼圖、收到贈送會員。
  - 未知元件存成 `system` 並保存 `rawTag`，`console.info` 一次。
  - 佔位元素與跑馬燈項目略過。
  - 置頂送 `SAVE_PINNED`，同 id 不重送；降落橫幅以內容雜湊產生 id。
- **修剪（F-01）**：
  - 每次變動後只要超過 45 則，就移除最舊的已處理節點；另有 3.5 秒保底。
  - 暫停、失去連線、沒有 videoId 時不擷取，直接移除最舊節點。
  - 等待場次資訊期間不移除未擷取的節點，避免遺漏回溯訊息。
- **批次與重試（3.2）**：
  - 滿 50 則立即送出，未滿時 1 秒保底；一次最多送 200 則。
  - 失敗時依 0.5／1／2 秒重試；仍失敗就留到下一批，上限 2000 則，超過時丟棄最舊的並計數。
  - 回應 `ok: false` 不重試；回應 `paused` 時停止擷取，但照常修剪。
  - 擴充功能重新載入後，舊頁面停止送出、照常修剪。
- **刪除（審查 3.3）**：
  - 偵測到刪除時，先等該訊息所在的批次寫入完成，再送 `MESSAGE_DELETED`。
  - 回 `found: false` 時，下一批寫入後重送一次；擷取時已是刪除狀態的訊息直接存 `deleted: true`。
- **時間**：
  - 直播讀 `#timestamp` 當地時間；它只到分鐘，秒數以擷取時間補足（v29 補充）。
  - 重播讀影片時間作為 offset。
  - 開播時間：
    - 有 `endDate` → 已結束。
    - `startDate` 已過 → 已開播。
    - `startDate` 未到 → 待機室：`phase: pre`，offset 先存 `null`，開播後由 background 回填。
- **F-18**：重播收錄開始前最多等 3 秒取得影片長度，連同 `CAPTURE_START` 送出。
- **F-15**：收到暫停設定變更時重新判斷；恢復後開新的 session，並回溯擷取畫面上現有的訊息。
- **F-19 自動接手**：
  - background 收到彈出視窗的 `CAPTURE_END` 後通知主分頁。
  - 主分頁的聊天室收起時，按影片下方卡片的原生「開啟面板」展開，chat frame 載入後自動開始收錄。
  - 「預設開啟優化面板」屬於 T5。
- **診斷輸出**（只有筆數、屬性名稱與時間，不含訊息文字與標題）：
  - `[ytcas] 場次資訊（診斷）`：top frame。
  - `[ytcas] 聊天室環境（診斷）`：chat frame。
  - `[ytcas] 聊天室 iframe 狀態（診斷）`：top frame，iframe 出現、消失或換頁時輸出。
  - `[ytcas] 收錄統計`：每分鐘與結束時各一次，含 `added`、`idMerged`、`fpMerged`、`dropped`、`trimmed`、`domNodes` 等。

## 4. 問題、事件與偏離規格之處
1. **舊資料不在 Chrome 裡**（第 0 節）。
2. **時間戳精度**（v29 已寫入規格）：`#timestamp` 只到分鐘，若照字面還原，同一分鐘內的訊息時間會相同，時間軸同步與指紋去重都會失準。因此用擷取時間補足秒數，但限制在該分鐘範圍內。
3. **開播判斷是暫定做法**：`startDate` 已過就視為已開播。如果直播延後開始（預定時間已過、還沒開播），那段待機室訊息會被標成 `live`，而且 `startedAt` 一旦寫入就不會被覆蓋。等第 5 節 B 的診斷結果出來再修正。
4. **SPA 導航後 microdata 是否更新**：top frame 在 `yt-navigate-finish` 後 800ms 才送場次資訊。若 YouTube 在站內換頁時沒有更新 meta，新影片可能拿到舊的開播時間。待實機確認；chat frame 會隨換頁重新載入，`videoId` 本身不受影響。
5. **關閉彈出視窗的 `CAPTURE_END`**：在 `pagehide` 送出；Chrome 直接關閉視窗時可能送不到，此時不會觸發自動接手。session 會由 background 以最後寫入時間補上結束時間。
6. **F-12 自動切到「即時聊天室」**沒有在 T3 做：規格是在開啟優化面板時執行，屬 T5。在那之前，收錄到的是 YouTube 目前選擇的模式，預設為「重點聊天室訊息」，**會漏掉部分訊息**。實測時建議手動切到「即時聊天室」。
7. **一次最多送 200 則**：補送積壓時合併送出，規格只規定「滿 50 立即送」，這是補充。
8. **彈出視窗的重播記為 `replay`**：offset 來自影片時間，比照嵌入式重播；直播的彈出視窗記為 `popout`。
9. 本輪沒有任何對 YouTube 或外部網站的請求；測試頁只連 `127.0.0.1`。

> 所有 Console 指令只輸出筆數、屬性或時間，不含訊息內容。DevTools 的 Console 左上角可以切換 frame：`top` 是頁面，`live_chat` 是聊天室 iframe，Service Worker 由擴充功能卡片的「Service Worker」連結開啟。

1. 完全關閉 Chrome（工作列、系統匣都沒有）。
2. 到 `%LOCALAPPDATA%\Google\Chrome\User Data\Default\IndexedDB\`，把 `chrome-extension_ejdhefdjjjlajfilfijnanippgdcdeoi_0.indexeddb.leveldb` **改名**為 `…leveldb.v3-empty`（保留，不要刪除）。
3. 把 `E:\Tool\ChromeExtensions\indexeddb_bak\bak_v1\chrome-extension_ejdhefdjjjlajfilfijnanippgdcdeoi_0.indexeddb.leveldb` **複製**（不是移動）回上述位置。
4. 開啟 Chrome → `chrome://extensions` → 本套件按 🔄（**不要按「移除」**）→ 點「Service Worker」開 DevTools，在 Console 執行：
   ```js
   await YTCAS_BG.autoMigrateLegacy(true).then(r => ({ exists: r.exists, legacyCounts: r.legacyCounts, legacyCountsAfter: r.legacyCountsAfter, migratedCounts: r.migratedCounts }))
   ```

### B. 直播收錄（約 10 分鐘）
1. 開一個進行中的直播，最好是高流量的。重新整理頁面，並把聊天室切到「即時聊天室」（見第 4 節第 6 點）。
2. Console 篩選 `[ytcas]`：
   - 在 `top` 找到「場次資訊（診斷）」那一行，展開後貼給我。
   - 切到 `live_chat` frame，找到「聊天室環境（診斷）」那一行，展開後貼給我。
3. 等 5 分鐘以上，在 `live_chat` frame 執行：
   ```js
   document.querySelectorAll('#item-list #items > *').length
   ```
   把數字貼給我。也貼最近一行「收錄統計」（展開後的物件）。
4. 在 Service Worker Console 執行，隔 1 分鐘再執行一次，兩次都貼給我：
   ```js
   (await YTCAS_DB.listStreams()).map(s => ({ v: s.videoId.slice(0, 4), n: s.messageCount, live: s.liveCaptureCount, popout: s.popoutCaptureCount, replay: s.replayCaptureCount }))
   ```
5. 如果剛好有訊息被管理員刪除：Console 會在之後的「收錄統計」顯示 `deleted ≥ 1`。若畫面上看到被刪的訊息、統計卻還是 0，請告訴我。

### C. 背景分頁 30 分鐘
- 直播分頁開著，切到其他分頁 30 分鐘以上。
- 切回來後**立刻**在 `live_chat` frame 執行 B-3 的指令，貼數字給我。

### D. 彈出式聊天室（F-19 AC a、b、e、g）
1. 在聊天室 `⋮` 選單選「在彈出式視窗中開啟聊天室」。
   - 主分頁 `top` 的 Console 會出現「聊天室 iframe 狀態（診斷）」，**請貼給我**；這是彈出視窗開啟時主分頁的狀態。
   - 在彈出視窗按 F12，貼「聊天室環境（診斷）」那一行。
2. 兩邊同開 5 分鐘後，貼彈出視窗與主分頁 `live_chat` 各自最近的「收錄統計」（AC b，看 `idMerged`）。
3. 關閉彈出視窗 → 再開 → 再關，重複 3 次。
   - 每次關閉後，看主分頁 5 秒內是否恢復收錄（AC g）：聊天室若被收起，應自動展開。
   - 記錄每次的情形。
4. 最後執行 B-4 的指令（AC e）。

### E. 直播／重播 id 一致性（直播結束、VOD 可看重播後再做）
1. 開 B 那場直播的 VOD，從頭播放（或跳到 B 有收錄的時段）約 5 分鐘。
2. 在 `live_chat_replay` frame 貼最近的「收錄統計」。
   - `idMerged` 遠大於 `fpMerged` → 直播與重播的 id 相同。
   - 反過來 → 不同，後備去重在運作。
