## 1. 摘要
- 使用者的 T1 實測證實方案 A 的關鍵前提全部成立，**F-10 定案方案 A**。關鍵前提指：裁切區可穿透、露出區可互動、不裁切時原生彈窗正常、下層為擴充功能 iframe 時同樣成立。
- 實測發現 3 個問題，本輪全部處理：
  1. **劇院模式錯位**：面板改為插入 `ytd-live-chat-frame` 內，clip 改套在 `iframe#chatframe`，不再換算座標。
  2. **頁面層付款視窗沒被偵測到**：PoC 新增頁面層大型浮層偵測，並提供 Console 診斷指令，用來取得實際選擇器。
  3. **浮動控制盒遮擋畫面**：移除所有浮動元素。SPEC 新增 10.1 原則 6「不遮擋影片與頁面主體」，並寫進 CLAUDE.md。
- 露出高度實測出現 84px 與 58px 兩種，證實不能寫死。SPEC 6.3 改為一律動態量測，PoC 新增自動量測模式。

## 3. PoC 修正內容（`f1679d6`）

| 項目 | v22 版 | v23 版 |
|---|---|---|
| 面板位置 | 插在 `ytd-live-chat-frame` 的父元素，用 `getBoundingClientRect()` 換算座標，每秒輪詢重排 | 插在 `ytd-live-chat-frame` **內**、`iframe#chatframe` 前，`position:absolute; inset:0 0 auto 0`，高度 = iframe 高度（`ResizeObserver`），跟著聊天室一起被搬移 |
| clip 對象 | `ytd-live-chat-frame` | `iframe#chatframe`：`inset(calc(100% - 露出值) 0 0 0)` |
| YouTube 重新渲染 | 無處理 | `MutationObserver` 監看聊天室，面板被移除或 iframe 被替換時自動重新插入 |
| 開關 | 左下角浮動按鈕 | 「隱藏聊天室」列右側的「**PoC 測試**」（F-09 預定位置）＋ Alt+Shift+P |
| 控制項 | 左下角浮動控制盒 | 面板頂部一列狀態，可展開／收合（預設收合） |
| 不裁切 | 控制盒勾選 | 聊天室列上的「**不裁切／恢復裁切**」按鈕＋ Alt+Shift+U |
| 露出高度 | 手動滑桿（預設 84） | **自動（預設）**：新增 `src/poc/poc-chat.js`，在 chat frame 量測 `#input-panel`，回報高度、頂端到 iframe 底邊的距離、子元素標籤和高度（不含文字）；也可切回手動滑桿 |
| 頁面彈窗偵測 | 只看 `ytd-popup-container` | 另掃描 `body` 前兩層可見的大型 `position:fixed` 元素（標示「頁面浮層」），只讀標籤和 id |
| 浮動元素 | 有 | **無**（模擬頁驗證 `position:fixed` 的 PoC 元素為 0） |

`manifest.json` 新增一組 content script：`live_chat*`、`live_chat_replay*` 加上 `all_frames`，載入 `poc-chat.js`。T9 發版時與其他 PoC 一起移除。

**自動露出值的算法**：用「`#input-panel` 頂端到 iframe 底邊的距離」，不是 `#input-panel` 本身的高度。這樣即使輸入區下方還有其他元素，也能完整露出。兩個數字都會顯示，補測時可以比對，作為 T6 正式實作時取哪個值的依據。
