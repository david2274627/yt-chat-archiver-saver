## 5. 驗證結果

### 5.1 `theme.js` 單元測試（Node，模擬 DOM、`chrome.storage`、`matchMedia`）
7 組全部通過：
1. 選「自動」且系統為淺色時套用淺色；系統改成深色的事件發生後，立即改為深色。
2. 選「淺色」後，不論系統怎麼變都維持淺色，且設定會寫入 storage。
3. 「切換主題」依「淺色 → 深色 → 自動」循環。
4. 載入時讀取 storage 裡既有的設定並套用。
5. 內嵌面板的來源模式：
   - 還沒收到 YouTube 外觀前，先用系統設定猜測；
   - 只接受來自 `https://www.youtube.com` 且確實是父頁面送來的 `THEME`；origin 或來源不符時一律忽略；
   - 收到 YouTube 外觀後，系統設定變更不再影響。
6. 沒有 `chrome` 物件時（匯出 HTML），以「自動」跟隨系統，也可以只在本頁手動切換。
7. 傳入無效的設定值時退回「自動」。

### 5.2 設計稿（本機 `127.0.0.1` 伺服器，在我自己開的分頁裡測）
- Console 沒有錯誤；頁面上沒有 `position: fixed` 元素；視窗 648px 寬時沒有橫向捲動。
- **膠囊列 4 個在各寬度都是單列**：

  | 面板寬度 | 內容寬度／可用寬度 | 顯示方式 |
  |---|---|---|
  | 300px | 284／284 | 「全部」只顯示數字，並省略膠囊前的圖示 |
  | 340px | 324／324 | 「全部」只顯示數字 |
  | 360px | 344／344 | 「全部」只顯示數字 |
  | 450px | 434／434 | 完整顯示文字 |

  第一版的判斷門檻設在 340px，結果 360px 的面板溢出 4px，所以門檻改為「面板 ≤ 376px」，另外加上 300px 的規則。
- **主題按鈕**：
  - 頂部、後台、popup 三組按鈕任按一組，三組（含 ⋯ 選單顯示的目前模式）都會同步；
  - 狀態文字會正確顯示「自動：系統目前為深色 → 套用深色」或「手動：固定淺色（系統目前為深色）」；
  - ⋯ 選單的「切換主題」依「深色 → 自動」循環；
  - 深色時 `--ytcas-bg` 為 `#15121d`。
- **「自動」跟隨系統**：
  - 以瀏覽器的模擬深色模式重新整理頁面，會正確套用深色。
  - 但這個模擬工具改變設定時**不會發出**「系統主題已變更」的事件：我另外掛的獨立監聽器也收不到，所以這不是 `theme.js` 的問題。
  - 真正切換 Windows 設定時，Chrome 會發出這個事件，事件的處理邏輯已由 5.1 第 1 項涵蓋。**「當場即時切換」需要你在實機確認**（第 7 節）。

## 6. 問題、事件與偏離之處
1. **設計稿改為載入 `src` 內的檔案**：原本 10.8 要求設計稿「無外部相依」，現在設計稿會載入 repo 內的 `../src/styles/*.css` 與 `../src/theme.js`。這些仍是本機檔案、不需要網路，直接雙擊就能開啟。好處是設計稿與實作用的是同一份 token 和樣式，不會兩邊不一致（D2 完成條件）。已寫入 SPEC 10.8。
2. **`components.css`**：SPEC 的 D2 寫的是「token 與元件 CSS」，本輪把設計稿的元件樣式搬進 `src/styles/components.css`。T4 實作時直接沿用，屆時可能需要拆檔或微調命名。
3. **`DB_VERSION` 仍是 1**：規格已寫好 v2，但實際升版與遷移屬於 T2，本輪沒有改 `constants.js` 的版本號。
4. **審查報告 4.2 的「深淺程度」**：依第 5 節使用者的決定，不做明暗滑桿（見第 2 節附註）。
5. **自動跟隨系統的即時切換**：只能在實機驗證（見 5.2）。
6. 本輪沒有發生誤操作事件。瀏覽器只操作我自己開的 `127.0.0.1` 設計稿分頁，沒有碰任何 YouTube 頁面。`_to_delete/` 本輪沒有出現。
