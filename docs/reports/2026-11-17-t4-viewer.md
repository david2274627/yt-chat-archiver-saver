## 規格 v38：實作時確定的細節
這些都已寫進 SPEC，有不同意見請告訴我。
- **膠囊數字**：數字為套用使用者、關鍵字、隱藏已刪除這些條件後的筆數。例如搜尋「草」時，「SC／禮物 3」表示 SC 裡有 3 則含「草」。
- **使用者欄**：部分比對顯示名稱、`@handle`；點列表中的名稱改為精確篩選該作者，以 chip 顯示。
- **關鍵字**：
  - 不分大小寫，全形可以找到半形（NFKC）。
  - 也比對表符的名稱（例如 `:tea:`）與禮物名稱。
- **多則置頂**：卡片顯示最新一則，展開後列出較早的置頂。
- **時間碼**：

  | 情況 | 顯示 | 可點 |
  |---|---|---|
  | 直播中、有 offset | `1:02:05` | 可點 |
  | 開播時間尚未確認 | 當地時間 | 不可點 |
  | 待機室 | 開播前 12:34 | 不可點 |
  | 結束後 | 結束後 3:05 | 不可點 |
  | **24 小時長期直播**（追加八 C） | 當地時間，跨日加日期 | 不可點，T5 再處理 |

  - 在後台分頁點時間碼，會在新分頁開啟 YouTube 該時間點。
  - 內嵌面板的跳轉在 T5 接上。
- **捲動起點**：
  - 內嵌面板與直播中的場次從最底部開始，並自動跟隨。
  - 已結束的場次從最上方開始，按鈕文字為「↓ 跳到最新」。
- **SC 文字色**：依底色以對比度選黑或白。
  - 例如 YouTube 藍色 SC（`#1e88e5`）算出來黑字對比 5.5、白字 3.8，所以用**黑字**，與 YouTube 原生的白字不同。
  - 想要和 YouTube 一致請告訴我。
- **後台分頁**：T7 之前用上方的下拉選單切換場次；T7 改為側欄場次清單。

## 開發中發現並修正的問題
- **背景分頁不觸發 `requestAnimationFrame`**：瀏覽器窗格隱藏時清單不會重繪，測試卡住。
  - 改為頁面隱藏時以 `setTimeout` 排程。
  - 實際使用時也有幫助：後台分頁放在背景、收到新訊息時清單仍保持正確。
- **頻道名稱更新後可見列沒有重繪**：推播更新時沿用了舊節點。改為內容改變時重新繪製可見列。
- **測試頁曾對外載入圖片**：測試資料含白名單網域的圖片網址，第一次執行時瀏覽器實際向 `yt3.ggpht.com`、`lh3.googleusercontent.com` 請求了**虛構的路徑**（`/emo.png`、`/s.png`），不含任何使用者資料。
  - 已在 `test-viewer.html` 加上 CSP（`img-src 'self' data:`）。
  - 之後的執行只連 `127.0.0.1`；README 也記入這條規則。
- **測試伺服器快取**：Python 內建伺服器讓瀏覽器快取舊的 `db.js`。改用不快取的本機伺服器（只綁 `127.0.0.1`，腳本放在暫存區，不進 repo）。

## 限制與注意
- **禮物卡**：禮物內部結構還沒確認（T3 事件型項目），目前顯示擷取到的文字；有禮物名稱與數量欄位時才顯示「送出 櫻花雨 ×3」。
- **頭像與表符圖片**：
  - 只顯示白名單網域，載入失敗時頭像退回首字。
  - 直播收錄的訊息多半沒有頭像網址（T3 實機結構），會看到首字圓點，這是預期行為。
- **場次標題**：沒有標題的場次（例如只收到 videoId）在下拉選單中顯示 videoId。

## 需要你做的事
1. `chrome://extensions` 對本套件按 🔄（**不要按「移除」**）。
2. 開啟後台檢視器：`chrome-extension://ejdhefdjjjlajfilfijnanippgdcdeoi/src/viewer.html`（HANDOFF「三之二」也有）。
3. 用下拉選單切換幾個場次，特別是：
   - **訊息最多的一場**：看開啟速度、捲動是否順暢。
   - **24 小時直播 `m_dh…`**：時間碼應顯示當地時間。
   - **有待機室的場次**：例如 `3LKG…`，應看到「直播開始前（待機室）」分隔線。
   - **從 v2.6.0 遷移來的舊場次**：如果有。
4. 試用：膠囊、使用者過濾、點名稱、關鍵字（中文、英文、表符名稱）、⋯ →「隱藏已刪除訊息」「切換主題」、點置頂卡片展開。
5. 如果有正在收錄的直播：檢視器開著那一場，放在最底部，看新訊息是否每秒左右出現並自動跟隨；往上捲後出現「↓ 恢復自動捲動」。
6. 網址加 `&embed=1`（例如 `viewer.html?embed=1&v=影片ID`），把視窗縮到約 360px 寬，看窄版面。
