## 做法

### chat frame（聊天室 iframe 內，`src/chat-input.js`）
- **底部互動區高度**：沿用 T1 PoC 的白名單算法，也就是 iframe 底邊減去下列元素中最高的頂端。
  - 白名單：投票卡 `#chat > #action-panel`、置頂列、`#panel-pages`、`#input-panel`。
  - 覆蓋層 `ytls-widget-overlay-manager` 的可見子元素也算，但量出來超過 iframe 高度 60% 時不採計（避開 T1 那次 545px 的錯誤值）。
  - 都量不到時，用 `#input-panel` 頂端。
  - VOD 的 `#input-panel` 高度是 0，視為沒有輸入區。
- **彈窗**：表符選單、購買流程、下拉選單、對話框，取最上方的頂端。
  - `$` 選單長在 `#input-panel` 內，展開時輸入區本身變高，已經算在高度裡，所以不另外當成彈窗。
  - 頂部列內的下拉選單不算：F-12 自動切換時會短暫展開，而且頂部列本來就被裁掉。
- **何時回報**：輸入區或置頂列大小改變、點擊或按鍵之後、每 500ms 保底檢查。**狀態有變才送**，只有數字與布林。
- **面板開著時**：以 `visibility: hidden` 隱藏原生訊息列表與頂部列（SPEC 6.2 第 2 點）。
  - 不改任何 `height`／`display`，避開 6.1 列出的失敗路線。
  - 退讓或關閉面板時立即還原。

### top frame（`src/panel.js`）
| 狀態 | 條件 | 裁切 |
|---|---|---|
| 收起 | 有輸入區、沒有彈窗 | 只露出底部互動區 `inset(calc(100% - Npx) 0 0 0)` |
| 彈窗展開 | 表符選單、購買流程等 | 只露出彈窗頂端上方 8px 以下 |
| 頁面層付款視窗 | 「完成購買程序」視窗開著 | **沿用前一個狀態**，兩邊都關了才回到收起（避免流程中閃回） |
| 無輸入區 | VOD、量測不到 | 面板全高 |
| 量測過期 | 還沒收到、或 iframe 高度已改變 | 面板全高，等重新量測，不套用舊值 |
| 退讓 | 劇院模式、聊天室太矮、**面板剩餘高度 < 80px** | 移除裁切、隱藏面板（與 T5 相同） |

- **面板底部留白**：top 把底部互動區高度告訴面板，面板整體加 `padding-bottom`。最後幾則訊息與「↓ 回到播放位置」都在原生輸入列之上。
- **重新量測**：面板開啟、聊天室 iframe 重新載入時，主動要求聊天室重新量一次。
- **記錄**：裁切狀態改變時記一筆（模式、原因）到 F-20 P4（`panel-clip`），沒有內容。

### test-diag-page 的已知不穩定
- **根因**：「記錄 10 分鐘」時，診斷頁先用自己的時間算出停止時間，background 收到後才取開始時間（晚幾毫秒），所以實際只記 599,999 ms。
- 這不只是測試的問題，實際記錄也會少幾毫秒。
- **修正**：改成同時送時長，background 以實際開始時間加上時長計算停止時間。
- **測試**：加了一個確定性的測試，故意讓停止時間早 3 毫秒來重現。連跑 3 次都是 11／11。

## 事件
- **測試寫錯，修正後才通過**：
  - 裁切值的計算結果被 Chrome 序列化成 `calc(-114px + 100%)`，我的比對寫成 `calc(100% - 114px)`。
  - 更根本的是 `clip-path` 有 120ms 的轉場，瀏覽器面板隱藏時轉場不前進，計算值停在起點。
  - 改為比對 iframe 上實際套用的 `--ytcas-clip`，程式本身沒有改。
  - 除錯時在 `panel.js` 暫時加了一行 `console.info`，已在提交前移除。
- **「只接受 parent」的測試一開始寫錯**：從本頁呼叫 iframe 的 `postMessage` 時，來源是本頁，不是 iframe。改用 iframe 內定義的函式送出，與既有的 `chat-env.html` 相同做法。
- **瀏覽器分頁**：我編輯測試夾具 `chat-env.html` 時，app 自動在瀏覽器面板開了該本機檔案的分頁（tab-1），我沒有操作它；測試都在我自己開的 tab-2。
- **程序**：測試伺服器以 PID 19952 啟動，結束時依這個 PID 結束，並確認已不存在。
- **其他**：沒有啟動其他瀏覽器，沒有對外連線。

## 需要你做的事（依環境分組，同一組可在同一場測完）
> **付款相關步驟只走到付款確認頁，不要真的付款。** 我不會、也不能替你操作付款頁面。

1. 【不限】`chrome://extensions` 對本套件按 🔄（**不要按「移除」**），再**重新整理** YouTube 分頁。
2. 【任何直播】（面板預設開啟）
   1. 面板底部**露出原生輸入列**，上方是面板，中間沒有空白框（AC 1）。
   2. 直接在輸入列打字並送出；送出後輸入列回到單行（AC 2）。
   3. 點表符按鈕：選單向上展開蓋在面板上，可以選表符並送出；關閉後回到單行（AC 3）。
   4. 面板上半部可以捲動、點時間碼、點名稱篩選（AC 5）。最後一則訊息不會被輸入列蓋住。
   5. 有置頂訊息或投票卡時，整塊都露出來，沒有被切掉，也沒有多露出原生訊息列表（AC 12）。
   6. 點 `$`：超級留言、超級貼圖、會員（有的話）各走到**付款確認頁**就關閉。檢查沒有文字重疊、沒有被裁切、沒有跑到頁面頂端（AC 4）。
3. 【VOD】打開有聊天重播的影片：面板全高，底部沒有露出任何東西（AC 6）。
4. 【不限】按面板的「關閉優化面板」：原生聊天室完全還原，訊息列表重新出現（AC 7）。再從聊天室頂部列的按鈕開回來。
5. 【任何直播】版面切換（AC 8、13、14）：
   - 切劇院模式 → 面板退讓（原生小框可用）→ 切回 → 面板自動恢復、底部輸入列再次露出。
   - 把視窗拉窄（單欄）與拉矮：仍露出輸入列，或在太矮時自動退讓。
   - 退讓期間的訊息仍在存檔中，切回後沒有重複。
6. 【任何直播】（T5.7）
   - `@无恋` 這類短 handle 的頭像可以開頻道。
   - 分頁放在背景一陣子再切回：那段期間的訊息時間碼前有淡色「≈」，滑鼠移上去說明只精確到分鐘。
7. 【待機室→開播】（T5.7，遇到時）開著待機室等到開播，**不要重新整理**：
   - 準時開播後約 1～2 分鐘，標頭轉為「直播中」。提早開播則約 2～3 分鐘（預定前 30 分鐘內）。
   - 開播後的訊息在「直播中」段。
   - 可以在 Service Worker 的 Console 執行 `await YTCAS_BG.streamTimes('影片ID')`，看 `liveConfirmed`。
8. 【大量訊息】本輪不需要。
9. （可選）如果有怪現象，開 F-20 診斷記錄（P1、P4、P7、P8）幾分鐘後匯出給我。
   - 裁切狀態的變化會記在 P4（`panel-clip`：模式、是否沿用、原因），頁面層付款視窗的開關也是（`panel-top-popup-open`／`-close`），都沒有內容。
