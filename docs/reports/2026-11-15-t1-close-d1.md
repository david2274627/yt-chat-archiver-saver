## 3. D1 設計稿內容
`design/mockups.html` 是單一 HTML 檔，沒有外部相依。頂部可切換「方向 A／B」「淺色／深色」，選擇會記在瀏覽器裡。

| 方向 | 風格 |
|---|---|
| **A 沉穩工具感** | 中性灰階、細邊框、小圓角（4／6px）、沉穩的藍色強調、訊息列較密。身分與類型靠文字色與細框徽章區分。適合長時間閱讀、想一次看到最多訊息 |
| **B 柔和現代感** | 帶紫的柔和底色、大圓角（8／14px）、以柔和陰影取代邊框、彩度較高的紫色強調、膠囊為實心底、留白較多 |

頁面依序展示：
1. **直播中的內嵌面板**：寬度 340／360／450px，搭配三種原生底部互動區：
   - 只有輸入列：57px
   - 置頂列＋輸入列：109px
   - 投票卡＋輸入列：239px

   畫面中還包含：頂部紅色「關閉優化面板」、預設收合成一行的置頂卡片（避免和原生置頂列重複）、「↓ 恢復自動捲動」。
2. **VOD 重播**：面板全高，目前播放位置的訊息有藍框；另有置頂卡片展開、搜尋中（使用者 chip 與關鍵字標示）、三種空狀態。
3. **訊息類型**：
   - 一般訊息，以及主播／管理員／會員的身分標示
   - 認證實況主發言、降落
   - Super Chat 四種等級色、超級貼圖
   - 新會員、會員里程碑、贈送會員、收到會員
   - 系統訊息
4. **開關按鈕三種位置**：
   - 頂部列 `⋮` 左邊的小圖示按鈕，滑鼠移上去顯示提示文字
   - 影片下方卡片「開啟面板」旁
   - 面板內的關閉鈕

   另有**劇院模式退讓**示意：兩顆按鈕都是虛線、淡色的停用樣式，不用紅色。
5. **後台檢視器**：側欄場次清單、匯入／匯出／刪除，以及刪除確認對話框。
6. **popup**：有聊天室與沒有聊天室兩種狀態。
7. **色票**：目前方向的 token 色票，切換方向與主題時會跟著變。

灰色虛線區塊代表 YouTube 原生畫面，不是套件 UI。全部為虛構資料，不使用 YouTube 標誌。影片上沒有任何套件元素。

## 4. 驗證結果

### 4.1 自動檢查
- JS 語法：`selectors.js`、`clip-path-poc.js`、`poc-chat.js` 都通過 `node --check`。
- PoC v24.2 在模擬頁上的檢查。模擬頁的聊天室內部依 `docs/youtube-dom-notes.md` 建構，依 SPEC 第 9 節，**只代表邏輯檢查通過，真實結構待實機**：
  - 有投票卡、無置頂列：露出 239px（與實機數字相符）。
  - 有投票卡、有置頂列：露出 291px。
  - 矮視窗（380px）加投票卡：面板可見高度不到 160px，改用後備算法並標示原因。
  - 劇院模式模擬（搬到其他容器並壓成 150px）：暫停，頂部列顯示「PoC 暫停」。
  - 搬回原容器並恢復 594px：自動恢復，面板與 iframe 誤差 0px。
- 設計稿：
  - 載入沒有 Console 錯誤。
  - 方向與主題切換正常（例如方向 B 深色的 `--ytcas-bg` 為 `#15121d`）。
  - 三個直播面板寬度分別為 340／360／450px。
  - 頁面上沒有 `position: fixed` 元素。
  - 窄視窗（648px）下不會出現橫向捲動。

## 5. 問題、事件與偏離之處
1. **投票卡與劇院模式恢復在實機還沒驗證**：這兩項是 v24.2 的修正。依審查指示不再單獨補測，`test-checklist.md` 標為 ⬜，留到 T6 依 6.5 AC 12、14 驗收。

3. **設計稿的圖示與 Super Chat 顏色**：
   - 圖示是自繪的 SVG，不是 YouTube 圖示。
   - SC 等級色依規格「使用訊息本身的等級顏色」，在設計稿中以假資料寫死，屬規格允許的例外。
4. **`_to_delete/` 又出現了**：沒有動，也沒有 commit。
5. 本輪沒有發生誤操作事件。瀏覽器只操作自己開的 `127.0.0.1` 模擬頁分頁。

## 6. 需要使用者做的事
1. 用 Chrome 開啟 `E:\Tool\ChromeExtensions\yt-chat-archiver-saver\design\mockups.html`（直接雙擊，或把檔案拖進 Chrome）。
2. 用頂部按鈕切換「方向 A／B」與「淺色／深色」，四種組合都看一遍。
3. 回覆格式：
```
選定方向：A / B
要修改的地方（可選）：例如「B 的圓角小一點」「A 的強調色換成綠」「訊息列再密一點」「置頂卡片樣式改成…」
其他意見：
```
4. 決定 `_to_delete/` 是否刪除。
